## Discovery content (v2)

```json
{
  "v": 2,
  "mintUrl": "https://merchant.lacrypta.ar/api/coupons/mint",
  "claimUrl": "https://merchant.lacrypta.ar/api/coupons/claim"
}
```

CMS pubkey is tag `p` on the event — not in this JSON.

## Mint

```bash
curl -X POST https://merchant.lacrypta.ar/api/coupons/mint \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"couponId":"55b5ee4f-4dcc-4a6a-a58e-6d1d94d811a3"}'
```

## Preview

```bash
curl "https://merchant.lacrypta.ar/api/coupons/claim?nonce=hcLPDzERvvHzS4Vn0OLbAQ"
```

## Redeem

```bash
curl -X POST https://merchant.lacrypta.ar/api/coupons/claim \
  -H "Content-Type: application/json" \
  -d '{"nonce":"hcLPDzERvvHzS4Vn0OLbAQ"}'
```

## Refresh

```bash
curl -X POST https://merchant.lacrypta.ar/api/coupons/refresh \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: $(uuidgen)" \
  -d '{"nonce":"hcLPDzERvvHzS4Vn0OLbAQ"}'
```

Reuse the same key to retry — it replays, it does not mint twice. The old nonce
now previews as `refreshed`.

## Transfer

```bash
# 1. does the recipient take coupons?
curl -s https://wallet.example/.well-known/lnurlp/alice | jq .allowVouchers

# 2. hand it over — the receiver refreshes and answers
curl -X POST https://wallet.example/api/lud16/alice/cb \
  -H "Content-Type: application/json" \
  -d '{"action":"voucher","nonce":"hcLPDzERvvHzS4Vn0OLbAQ","voucher":{…}}'
# → {"status":"ACCEPTED"}
```
